#+AUTHOR: Ray Engineering
#+STARTUP: overview

* Purpose

This file is the quick-start foundation for building and running Ray in the
Zephyr container infrastructure with the required layering model:

- Spack owns core toolchain/runtime (Python, torch, jax)
- uv is used for all Python dependency installation
- Bazel builds Ray artifacts

For deep troubleshooting and full incident history, see:

- ~doc/zephyr_spack_uv_ray_build_enablement.org~

* Non-Negotiable Rules

1. Always activate the Spack environment before build/install/test commands.
2. Always use ~uv~ instead of ~pip~ for installs.
3. Always bind uv envs to Spack Python with ~--system-site-packages~.
4. Never let uv replace Spack torch/jax stack.
5. Always exclude these packages when installing Ray from source:
   - ~torch~
   - ~jax~
   - ~jaxlib~
   - ~triton~
6. For extension compilation, Python headers must come from Spack Python
   (~python3-config --includes~).

* Manual Build + Layered Install (Reference)

** Build

#+begin_src bash
source /opt/spack_src/share/spack/setup-env.sh
spack env activate /opt/spack_env/default >/dev/null

bazel --batch --output_user_root=/mnt/shared/bazel_cache/ray-sglang-codex-build \
  build //:ray_pkg --verbose_failures
#+end_src

** Focused tests

#+begin_src bash
bazel --batch --output_user_root=/mnt/shared/bazel_cache/ray-sglang-codex-build test \
  --test_output=errors \
  //src/ray/common/tests:source_location_test \
  //src/ray/raylet/tests:wait_manager_test
#+end_src

To include toolchain-sensitive diagnostics (not part of default comprehensive gate):

#+begin_src bash
RUN_TOOLCHAIN_SENSITIVE_TESTS=1 dev/zephyr/zephyr_ray.sh run-e2e-comprehensive
#+end_src

** uv layered install (Spack Python + excludes)

#+begin_src bash
SPACK_PYTHON="$(command -v python3)"
PY_INCLUDES="$(${SPACK_PYTHON}-config --includes)"

uv venv --python "$SPACK_PYTHON" --system-site-packages .venv-ray-pkg-py313
source .venv-ray-pkg-py313/bin/activate

cat > /tmp/ray_uv_excludes.txt <<'EOF'
torch
jax
jaxlib
triton
EOF

CFLAGS="${PY_INCLUDES} ${CFLAGS:-}" \
CPPFLAGS="${PY_INCLUDES} ${CPPFLAGS:-}" \
SKIP_BAZEL_BUILD=1 RAY_BUILD_REDIS=0 \
uv pip install --python "$(pwd)/.venv-ray-pkg-py313/bin/python" \
  --excludes /tmp/ray_uv_excludes.txt ./python
#+end_src

* Common Pitfalls and Recovery

** Dead compose container (~zephyr-ray~)

Symptom:
- ~container is marked for removal and cannot be started~

Recovery:

#+begin_src bash
docker rm -f zephyr-ray || true
WORKSPACE_DIR=/mnt/data_infra/workspace/ray \
  docker compose -f dev/zephyr/docker-compose.zephyr-ray.yml down --remove-orphans
#+end_src

** Stale ownership on generated or build dirs

Symptom:
- ~Permission denied~ while cleaning ~python/build~ or generated protobuf paths

Recovery:
- run the native e2e preflight stage (included in ~dev/zephyr_ray_e2e_validate.sh~)
- if needed, re-normalize ownership in container before re-run

** Dashboard crash

Symptom:
- ~Failed to start the dashboard, return code -11~

Status:
- known TODO/non-blocking for current build-and-runtime validation
- use ~include_dashboard=False~ in workload checks

* Operational Notes

- Reusing Bazel and Bazelisk caches is expected and recommended.
- If the external Bazel endpoint is flaky, retry after connectivity recovers; cached
  Bazel binary under ~bazelisk_cache~ eliminates repeated downloads.
- Keep this guide aligned with script behavior when changing
  ~dev/zephyr_ray_e2e_validate.sh~ or the skill runner.
