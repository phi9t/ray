### C7: Tensor Parallelism

**Not feasible.** Tensor parallelism splits individual weight matrices (attention heads, MLP columns) across GPUs with synchronized AllReduce after each layer. This requires:
- Megatron-LM or NeMo framework (not HuggingFace Trainer)
- High-bandwidth interconnect (NVLink, not PCIe 3.0)
- Significant engineering overhead for models this small

For 0.6B-4B models on PCIe 3.0, the communication overhead would exceed any memory benefit.

### C8: Context/Sequence Parallelism

**Not feasible.** Sequence parallelism (ring attention) splits the sequence dimension across GPUs, requiring each GPU to compute attention on its chunk and pass KV slices via ring communication. Available implementations (ring-flash-attn, DeepSpeed Ulysses) require:
- Flash Attention 2 (needs CC >= 8.0, we have CC 6.1)
- High-bandwidth interconnect for the ring communication pattern

Pascal GPUs cannot run Flash Attention kernels, making this approach impossible.

### 4B

- **Max throughput**: 216.9 tok/s (seq=128, bs=2, B3_qlora)
- **Max sequence length**: 1024 tokens
- **Recommended config**: QLoRA+GC, seq=1024, bs=1
- **Best multi-GPU**: 185.9 tok/s (C4_pipeline)

### Key Takeaways

1. **QLoRA + Gradient Checkpointing** is the most effective single-GPU strategy for memory-constrained training on Pascal GPUs
2. **Gradient accumulation** provides free effective batch scaling at constant memory
3. **Pipeline parallelism** (device_map='auto') is the most practical multi-GPU approach for models that don't fit on a single GPU
4. **DDP** provides near-linear throughput scaling for models that fit on each GPU
5. **Tensor and sequence parallelism** are not feasible on consumer Pascal GPUs
